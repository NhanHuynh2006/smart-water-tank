Smart Water Tank · Project 08

39

Four bugs taught us the most; all four are in Appendix A of the report. Each was invisible in the code and was found by counting something. First, an inverted relay: the configuration assumed the module was active low, it was active high, so every stop command started the pump while the telemetry said off. We proved the real state from the ripple of the motor current, twenty-seven millivolts when running versus four and a half when stopped. Second, the pump started after every reboot. At startup the firmware set the last valid reading time to now, so the sensor timeout counts from power up, but the validity flag was derived from that same timestamp, so for a few seconds the level was valid at zero percent and the controller saw an empty tank. We found it because automatic starts at 38 to 51 percent lined up with the sequence number restarting at one. Now the device stays in BOOT until a first reading is accepted. On the fifth of October the final firmware restarted with the tank at thirty three percent: the first level it published was thirty two, never zero, and the pump stayed off until the level drained below thirty. We will repeat this live. Third, a repeatable echo that is not the water: in the calibration, with the surface 7.9 to 8.7 centimetres from the sensor, all forty pings gave the same wrong value. A rule we had added, that a value repeated several times must be real, adopted it as an empty tank and started the pump every forty seconds. Consistency proves a reflector, not the right one; the rule is gone. Fourth, silent truncation: a telemetry message outgrew its buffer, the JSON library cut it without an error, and the MQTT library swallowed the parse exception. Everything looked alive, and nothing was stored.
