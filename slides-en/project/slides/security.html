Security model

AttackMitigation
Publish a pump command to the brokerPassword and ACL; the device account cannot write cmd
Call the API directlySession cookie: HttpOnly, SameSite Strict, Secure
Guess the password online5 failures in 5 minutes lock that address
Sniff Wi-Fi trafficNot mitigated in the lab: MQTT on port 1883. TLS on 8883 to deploy
Forge telemetry to fake a low levelFloat and raw guard live on the device
Spam commands to wear the pumpMinimum on 3 s and off 20 s, in firmware

The blue rows are stopped by physics and control design: no message can lift a float or switch the relay faster than the firmware allows. The orange row is our open gap: no end-to-end TLS.

Security is checked layer by layer. The broker needs a password and an ACL, the API needs a session cookie, and five wrong passwords lock the address. Two attacks are stopped by the control design itself: fake telemetry cannot cause overflow because the float is on the device, and spamming commands cannot wear the pump because of the minimum times. Our open gap is stated plainly: MQTT inside the lab is not encrypted; TLS on port 8883 is the deployment step.
